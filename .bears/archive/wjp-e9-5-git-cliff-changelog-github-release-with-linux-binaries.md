Build the release artifacts and cut the GitHub Release with conventional-commit notes. See SPEC §10, §12.

## Deliverables
- **`cliff.toml`** git-cliff config (conventional-commits → grouped notes: feat/fix/refactor/docs/…). Used to render the release body for the tag's commit range.
- **Binary build matrix** (release job, `needs: verify`):
  - `x86_64-unknown-linux-gnu`
  - `aarch64-unknown-linux-gnu`
  - Cross-compile strategy: prefer the native **`ubuntu-24.04-arm`** runner for aarch64 (cleanest for `ring` + bundled `libsqlite3-sys` C deps); `cross` or `cargo-zigbuild` are fallbacks. `SQLX_OFFLINE=true`.
  - The binary embeds all frontend assets via `include_*!`, so no extra asset step is needed.
  - Strip, then package `sagittarius-<version>-<target>.tar.gz`; emit a `SHA256SUMS` file.
- **GitHub Release** via `softprops/action-gh-release` (`contents: write`): body = git-cliff output for this tag, artifacts = the two tarballs + checksums. Pre-releases (tags with `-rc`/`-beta`) marked as prerelease.

## Design notes
- Release notes are generated **at tag time** by git-cliff; the committed `CHANGELOG.md` seeded in E9.3 is the human-facing rolling file (can be regenerated by the same cliff config — reconciled in E9.8).
- Keep artifact naming stable; E9.7's Docker build reuses these gnu binaries.

## Validation
- Pushing `vX.Y.Z` produces a GitHub Release with both Linux tarballs, `SHA256SUMS`, and changelog notes grouped by commit type. Downloaded binary runs `--version` correctly on the matching arch.
